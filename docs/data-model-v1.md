# 研途数据模型 V1

## 技术边界

- 当前只有一个活动考研目标。
- 用户明确要求浏览器本地保存，使用 IndexedDB；不接远程数据库。
- 数据库当前版本为 5。新增仓库或索引必须提升版本，并在升级事件中补建缺失结构，不能清空用户旧数据。
- JSON 备份必须包含格式名、版本、导出时间和全部实体。

## 实体关系

```text
Goal 1 ── N Subject
Subject 1 ── N Stage（可选）
Subject 1 ── N ContentNode（任意层级，可选）
Subject 1 ── N Task
Stage 0..1 ── N Task
ContentNode 0..1 ── N Task
Task 0..1 ── 1 TaskSchedule（当前计划日期及顺延统计）
Task 0..1 ── 1 RepeatRule
Task 1 ── N StudySession
Date 1 ── 0..1 DailyTarget
```

## IndexedDB 对象仓库

| 仓库 | 主键 | 说明 |
|---|---|---|
| meta | id | 数据版本、首次设置状态、最近备份时间 |
| goals | id | 当前目标固定使用 `current-goal` |
| subjects | id | 科目、颜色、目标分数和排序 |
| stages | id | 科目独立且可选的学习阶段 |
| contentNodes | id | 通过 parentId 构成任意层级学习目录 |
| tasks | id | 普通任务或数量进度任务 |
| taskSchedules | id | 任务的日期安排及顺延历史 |
| repeatRules | id | 重复任务规则 |
| studySessions | id | 每次真实专注记录 |
| dailyTargets | id | 某天自定义目标学习时长 |

## 关键约束

1. Task 必须关联 Subject；Stage 和 ContentNode 可空，但若存在必须属于同一 Subject。
2. 删除 Stage 或 ContentNode 不得级联删除 Task，必须解除关联或重新归属。
3. 计划日期、截止日期、实际完成时间分开存储。
4. “逾期”由日期和完成状态计算，不作为持久状态。
5. 自动顺延只修改当前计划日期，保留原计划日期、连续顺延次数和累计延迟天数。
6. StudySession 不因 Task 改期或删除而丢失；删除任务时解除历史专注记录的任务关联，但保留科目与时长统计。
7. 实际学习时长、任务进度、掌握程度独立存储。
8. 长期进度按预计耗时加权；未估时任务暂按 60 分钟、所有任务至少按 15 分钟计，避免短任务刷高进度。
9. 重复任务不预生成无限记录；完成本次后只生成下一次，用户始终能编辑或终止规则。

## 当前 MVP 已实现

- 首次设置、单一当前考研目标、科目管理。
- 科目独立且可选的阶段、任意层级学习内容。
- 普通任务、数量进度任务、日期安排、截止日期、自动顺延。
- 每天、每周指定日、间隔天数三种重复规则。
- 任务编辑、归档和一键完成后的可选实际耗时/掌握程度反馈。
- 正计时、倒计时、每日目标学习时长和学习记录。
- 未来七天计划、逾期区、按预计时长加权的科目/总进度、近七天复盘。
- IndexedDB 本地持久化、版本化 JSON 导出与恢复；云同步仅保留说明，不上传数据。
